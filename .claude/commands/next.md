너는 이 프로젝트의 **PM(메인 세션)**이다. 사용자가 "다음 할일"을 요청했다. 아래 절차로 **계획서의 다음 Task 한 단위**를 정확히 파악해 브리핑하고, 그 단위를 실행한다(커밋은 제외 — 마감은 `/wrap` 담당).

## 작업 큐가 어디에 있나

이 프로젝트는 STATUS.md 대신 다음을 작업 큐로 쓴다:
- **구현 계획서** — `docs/superpowers/plans/` 중 **가장 최근 날짜** 파일. Phase/Task/Step 체크박스(`- [ ]`)가 진행 단위.
- **TaskList** — 세션 내 작업 목록(`[P1-1] ...` 형식). 계획서 Task와 1:1 대응.
- **차터** — `docs/project_charter.md` (마일스톤 맥락).

## 절차

1. **현황 읽기** — 최신 계획서와 TaskList를 읽는다. 차터로 현재 어느 마일스톤/Phase인지 맥락 확인.
2. **다음 Task 식별** — 계획서에서 **첫 미완(`- [ ]`) Task** = 이번 단위(맨 위 하나만). TaskList의 첫 `pending` 항목과 일치하는지 확인. 불일치하면 먼저 알린다.
3. **인계점 검증** — 그 Task가 손볼 파일·경로(`Files:` 블록)를 **실제로 열어** 계획과 코드 현실이 일치하는지 확인한다(placeholder 그대로인지, 선행 Task 산출물이 존재하는지). 불일치하면 그 사실을 먼저 보고하고 멈춘다.
4. **브리핑** (한국어, 간결) — 아래 출력 형식대로.
5. **실행** — 문제없으면 해당 TaskList 항목을 `in_progress`로 바꾸고, 계획서의 Step을 **순서대로 수행**한다. 코드 Step은 그대로 작성, 실행/검증 Step은 돌려 **검증까지 통과**시킨다.
   - ⚠️ **커밋은 하지 않는다.** 검증 통과 후 멈추고 사용자에게 결과를 보고한다(커밋·문서갱신·큐 승격은 `/wrap`).
   - **사람이 직접 해야 하는 단계**(예: 야간 1000ep 재학습, 실물 라즈베리파이 연동, GUI 데모 녹화)는 코드를 짜되 **실행 명령을 안내하고 멈춘다**(대신 실행하지 않음).
   - 무겁고 경계가 분명한 **고립 단발 작업**만 사용자 승인 후 Agent 도구로 서브에이전트에 위임한다. 기본은 메인 세션 직접 수행.

## 출력 형식 (한국어, 간결)

- **📍 현재 위치** — 한 줄(어느 Phase, 전체 진행률 N/16).
- **▶ 다음 Task** — 계획서 Task 제목 + 한 줄 목적.
- **인계점** — 손볼 파일·코드 위치(클릭 가능한 `[file](path)` 링크)와 검증 결과(현실 일치 여부).
- **완료기준 / 검증** — 그 Task의 검증 Step(테스트·스모크·기대출력) 핵심만 불릿.
- **이후 큐** — 그다음 1~2개 Task 한 줄 미리보기.

## 마무리

브리핑 후 실행을 진행한다. 검증 통과하면 **"검증 통과. `/wrap`으로 마감할까요?"**를 묻고 멈춘다. 검증 실패·인계점 불일치면 마감하지 말고 원인을 보고한다.
