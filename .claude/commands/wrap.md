너는 이 프로젝트의 **PM(메인 세션)**이다. 이번 단계(계획서 Task 한 단위) 작업이 끝났다. 다음 단계가 계획서·docs만 보고 이어갈 수 있도록 **마감 + 다음 단계 인계**를 한다.

## 작업 큐 위치 (마감 대상)

- **구현 계획서** — `docs/superpowers/plans/` 중 가장 최근 파일(Task/Step 체크박스).
- **TaskList** — 세션 작업 목록(`[P1-1] ...`).
- **차터** — `docs/project_charter.md` (마일스톤).
- **README** — `README.md` (사용자 노출 변화 시).

## 0. 선행 게이트 (마감 전 필수)

이번 단계가 **실제로 완료·검증됐는지** 확인한다. 미검증이면 마감하지 말고 사용자에게 알린다.
- 코드 변경이 있었나? → 해당 검증 통과 확인:
  - 새 스크립트/관측/추론 → 해당 스모크·패리티 테스트 green (`tests/test_*.py` 실행 출력의 `[PASS]`).
  - 학습/평가 산출물 → 기대 파일 존재(`results/*.pth`/`*.csv`/`*.png`) + 형상 확인(차원·행수).
- 검증 증거 없이 "완료"로 적지 않는다(증거 우선). 필요하면 검증을 먼저 돌린다.

## 1. 계획서 갱신 (필수)

방금 끝낸 Task의 Step 체크박스를 `- [ ]` → `- [x]`로 바꾼다. Task 전체가 끝났으면 그 Task의 모든 Step을 체크.

## 2. TaskList 갱신 (필수)

해당 작업을 `completed`로 바꾼다. 그러면 다음 작업이 큐 맨 위가 된다. 이번 단계에서 발견한 후속 백로그·미결이 있으면 새 Task로 추가한다.

## 3. 차터 / README (해당 시)

- **Phase가 통째로 끝났으면** `docs/project_charter.md`의 마일스톤 표/체크박스를 토글한다(예: M5 진행→완료).
- 사용자가 보는 실행법·결과·기능에 변화가 있으면 `README.md`도 같은 내용으로 갱신.

## 4. 커밋 (게이트 통과 시에만)

문서 갱신(1~3)을 마친 뒤 이번 단계 변경을 **현재 브랜치에 커밋**한다. 푸시는 하지 않는다(사용자가 별도 요청 시만).

- **선결 조건**: 0번 게이트 통과 시에만 커밋. 미검증/실패면 커밋 말고 보고.
- `git status`로 범위 확인 후 이번 단계 산출물(코드 + 갱신 docs)을 함께 스테이징한다. 무관한 사전 변경분이 섞였으면 사용자에게 알리고 제외.
- **커밋 메시지**: 한국어 1줄 제목 + 필요 시 본문에 핵심 변경·검증 결과. 계획서 태그를 살려 적는다(예: `feat(e2): [P1-1] E2 검지기 생성`). 마지막 줄 트레일러:
  ```
  Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>
  ```
- 훅(`--no-verify` 등) 우회 금지. 훅 실패 시 원인 보고.

## 규율

- **한국어**로 작성.
- **stale 숫자 주의** — 빨리 낡는 수치(테스트 개수 등)는 박지 말고 "테스트 green"류로. (산출물 형상 수치는 기록 허용)
- **폴더 정돈** — 이번 단계에서 만든 일회성 정찰/디버그 스크립트가 있으면 삭제.
- **건드리지 말 것**: 비전·프로젝트 최종 목표·차터 핵심 구조.

## 마무리 보고 (간결)

- 이번 단계에서 무엇을 끝냈는지 1줄.
- 계획서/TaskList/차터/README 반영 요약.
- **커밋 결과**(짧은 해시). 게이트 미통과로 건너뛰었으면 그 사유. **푸시 안 했음** 명시.
- **다음 단계 = (승격된 큐 맨 위 Task 제목)** — 다음에 `/next`로 이어가면 됨을 안내.
